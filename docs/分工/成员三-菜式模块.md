# 成员三任务书 — 菜式模块

> 依据：《01-食匣详细构想.md》第二章 2.3 节（菜式）、《02-开发总计划.md》。逐周安排与总计划第四章一致。
> 你的模块是"菜式"——食匣的内容门面，详情页与倒计时条是全 App 设计最吃功夫的地方。

---

## 一、职责定位

- **模块责任（主）**：菜式模块全部 UI 与逻辑——推荐区、分类歌单、分类列表页、菜式详情页（步骤流 + 照片流 + 倒计时接入）、长按加入时序；
- **角色责任（辅）**：官方菜式内容录入（30–50 道）、菜式模块测试用例编写。

---

## 二、详细任务清单

### A. 内容建设（W1–W3，持续任务）

- [ ] 定菜式数据模板并与组长确认（食材清单含用量与是否必需、步骤含耗时/资源占用/安全标记——这些字段是时序算法的数据源，必须完整；含**适宜月份标签**字段，F12 期1 简易版的数据源）
- [ ] 录入官方菜式 30–50 道：步骤详细、每步有标准耗时；W2 完成 10–15 道、W3 累计 25–35 道、W4 补齐
- [ ] 分类打标双维度：主食材（海鲜/鸡肉/鸭肉/猪肉/牛肉/蔬菜/蛋豆/主食）+ 菜系（粤/川/湘/家常/快手/汤羹……）；同步打**适宜月份标签**（如「3–5 月」「全年」），供组长 F12 时令推荐按当前月匹配
- [ ] 菜式配图（按修订后的图片策略）：成品图与关键步骤图**优先收集真实高清图**（随数据录入逐批配图，小范围使用）；收集不到的列入缺图清单，由 AI 生成统一风格图兜底；无图步骤需优雅降级（构想 2.3.2：点击仅展开文字详解，不显示空图占位框）

### B. 菜式主页（W4，主攻周）

- [ ] 上半区推荐区：横滑 3:4 卡片（复用成员四的 `FbCard` 蒙版卡片组件），两类混排——「现在就能做」（绿点角标）/「差一点就能做」（橙点角标 + 蒙版标注"缺：蒜、料酒"）；数据来自组长的 `RecipeMatcher`
- [ ] 库关闭时降级为「为你推荐」静态排序（构想 2.3.1）
- [ ] 下半区分类歌单：双维度分类卡（封面图 + 分类名 + 菜式数量）
- [ ] 分类列表页：每行一条，左 64×64 圆角小图 + 菜名（Body）+ 极简介绍（Caption 次级色，"鲜辣下饭 · 25 分钟 · 中等难度"格式）；支持按耗时/难度/收藏排序

### C. 菜式详情页（W4–W5，设计重心）

- [ ] 垂直信息流按构想 2.3.2：成品大图（16:10 沉浸式）→ 菜名 + 属性胶囊行（耗时/难度/菜系/份量基准）→ 缺失食材区（库开启时，附 F1「一键加入购物清单」入口）→ 食材调料两列清单 → 分享者信息（期1 显示"食匣官方"）→ 步骤流程区
- [ ] **步骤流**：上方大字（H1 20px Bold）+ 下方分割线小字时间（Caption 12px 次级色 + 细分隔线）；步骤间空行 32px
- [ ] 点击步骤文字 → 照片流弹层（多图横滑）/短视频（如有）；步骤中的烹饪术语（如"焯水""勾芡"）可点开查看名词解释（F8 期1 范围，对接成员四维护的术语表数据与弹层组件）
- [ ] 点击分割线时间 → 唤出水平倒计时条（用成员四的公共倒计时条组件，多倒计时并行，命名 `Fb` 前缀）
- [ ] **F2 几人份缩放**（期1 必做，W5）：1–6 人份选择，食材/调料用量自动换算
- [ ] 底部吸底操作栏：收藏 / 想做 / 加入时序 / 我做过打卡

### D. 长按加入时序（W5）

- [ ] 菜式卡片、列表条目、详情页三处长按 → 悬浮操作浮层
- [ ] 主按钮「+」→ 点击变「✓」（轻动效）→ 再点取消；调组长的 `ScheduleRepository.add()`
- [ ] 浮层次级操作：收藏 / 想做 / 查看详情
- [ ] 已加入时序的菜式卡片右上角小勾角标

### E. 收尾（W5–W6）

- [ ] **F14 复盘笔记**（期1 必做，W6）：「我做过」打卡时可记一句心得（"下次少放半勺盐"），再次查看该菜式时展示
- [ ] 菜式模块 bug 清零，通过成员四 UI 走查

## 五、交付物清单

**代码**：`features/recipe/` 目录全部（主页、歌单、列表、详情、长按浮层）。
**内容**：官方菜式 30–50 道（结构化 JSON + 配图）。
**文档**：详细设计文档「菜式模块」章节、菜式模块测试用例表（交成员四汇总）。

## 六、验收标准

- 推荐区正确区分「可做 / 缺 N 样」并标注缺失项（与 `RecipeMatcher` 输出一致）；
- 详情页步骤流间距、字号、分割线样式 100% 符合构想 2.3.2；空行节奏舒适；
- F2 份量换算准确（1–6 人份切换后所有用量联动、无四舍五入失真）；F14 复盘笔记可记可查；
- 全部菜式带适宜月份标签；术语点开有解释、无术语的步骤不显示多余入口；
- 倒计时条点击唤出、多倒计时并行、页面切换后状态正确；
- 长按浮层三处入口行为一致，加入/取消状态全局同步（卡片角标实时反映）；
- 无图步骤、长菜名、超多步骤等边界显示优雅。

## 七、与其他模块的接口约定

| 你依赖 | 你提供 |
|---|---|
| 组长：`RecipeRepository`、`RecipeMatcher.match()`、`ScheduleRepository.add()` | 高质量菜式数据（步骤耗时/资源/安全标记字段完整——时序算法依赖它；适宜月份标签——F12 时令推荐依赖它） |
| 成员四：蒙版卡片（`FbCard`）、`FbSectionHeader`、`FbCountDownBar` 倒计时组件、术语解释弹层与术语表数据 | 菜式模块测试用例表（W6 交成员四） |
| 成员二：库存数据（推荐与缺失计算的数据源） | 长按浮层交互范式（动态模块期2 复用） |

**纪律**：倒计时一律用公共 `FbCountDownBar`，不自己写 Timer；倒计时按"结束时间戳"渲染（不依赖周期计数），保证挂起恢复正确（构想第四章技术规范）；改共享区文件需在 PR 标题加 `[shared]` 并群里同步。
