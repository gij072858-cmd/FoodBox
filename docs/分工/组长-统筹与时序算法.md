# 组长任务书 — 统筹、架构与时序算法

> 依据：《01-食匣详细构想.md》《02-开发总计划.md》。逐周安排与总计划第四章一致。

---

## 一、职责定位

你是组长，承担**三条线**：

1. **技术线（开发任务）**：项目架构搭建、数据层（Drift + Repository）、时序模块（规则引擎 + 执行页 + 悬浮计时条）、库存匹配推荐算法；
2. **统筹线（管理任务）**：排期与进度跟踪、接口裁决、Code Review、模块整合、GitHub 仓库管理；
3. **课程线（文档任务）**：五份课程文档的主笔/统稿、答辩 PPT 与演示材料。

你是全组任务量最大的人——这是组长的责任，也是答辩时"个人贡献"最有说服力的部分。

---

## 二、详细任务清单

### A. 架构与数据层（W1–W2）

- [ ] 编写《Flutter 环境搭建指南》（统一 SDK 版本，一人踩坑全组受益）
- [ ] 创建 GitHub 仓库、分支模型（main/dev/feature）、PR 模板（详见下方"协作分支规则"，已按 2026-09-11 决议改为直推 dev）
- [ ] 搭建脚手架：go_router 路由骨架、底部 TabBar + 首页顶部三 Tab 框架
- [ ] Drift 数据库：Item / Recipe / Step / ScheduleItem / Record / Profile 六张表（字段以构想文档附录为准，细化后冻结进 `docs/接口约定.md`）
- [ ] Repository 接口层：`PantryRepository` / `RecipeRepository` / `ScheduleRepository` / `ProfileRepository`——**接口与实现分离**，本地实现期1 完成，云端实现（Supabase，期2）仅留接口与注释说明
- [ ] 倒计时基础工具：`CountdownController`（结束时间戳方案，严禁 Timer 周期计数）
- [ ] 《数据层使用说明》一页纸（每个 Repository 一段示例代码）

### B. 推荐算法与数据工具（W4–W5）

- [ ] `RecipeMatcher.match(recipes, items)`：集合匹配 + 别名归一（维护 `alias_map.json`：西红柿=番茄 等）
- [ ] 输出三态：可做 / 缺 N 样（附缺失清单，阈值 ≤2，Q6-A）/ 差太多
- [ ] F12 时令推荐（简易版）：按当前月份匹配菜式"适宜月份"标签，推荐区加权
- [ ] F1 `ShoppingListGenerator`：缺失食材一键生成购物清单（可勾选划掉）
- [ ] F6 数据导出备份（W5）：库存/收藏/菜式/记录导出 JSON 到用户指定目录、可导入恢复、存储位置可在设置中修改

### C. 时序模块（W5–W6，期1 技术重心）

- [ ] 规则引擎 v1（构想 2.4.2）：贪心初排 → 安全规则校正（生熟分离强制插入清洁步骤、同灶台互斥、腌制前置）→ 衔接校正（热菜贴近完成时刻）→ 10% 末尾缓冲
- [ ] **开饭时间倒推**（Q7-A，期1 必做）：输入开饭时刻，倒推各步骤开始时刻与"几点开始动手"提示
- [ ] 引擎输出结构化时间线（步骤 + 起止时刻 + 并行标注 + 所属菜式色标）
- [ ] 时序页三态：待做清单（可移除/调份数）→ 排程结果预览 → 歌词滚动执行视图
- [ ] **步骤拖拽调整**（Q8-A，期1 必做）：长按拖拽交换步骤顺序，拖后重算时刻并校验安全规则，违规时震动 + 红条提示原因并回弹
- [ ] 全局悬浮计时条（构想 2.4.4）：跨页面存在，点击返回执行页
- [ ] 执行完成闭环：扣库存（调 `PantryRepository.consume`）→ 写做菜记录 → XP 结算与厨阶更新（构想 2.6 数值表）

### D. 统筹与整合（全程）

> **协作分支规则（2026-09-11 决议，替代原 PR 全流程）**：成员各自提交后**直接 push 到 dev**（免 PR）；**main 由组长在里程碑验收后合并**，组员不直推 main。两条兜底纪律：①共享区文件（`theme.dart`、`widgets/fb_*`、`接口约定.md`）改动前须在群里同步一句；②`main` 必须保持"验收通过即可跑"，任何未经组长合并的改动不得进入 main。约定细则以总计划 v1.4 为准。

- [ ] 每周五主持组会：里程碑验收（录屏存档）+ 下周任务确认
- [ ] W3 起对直推 dev 的改动做 Code Review（标准：能跑、合接口、无 UI 违规）；发现问题及时沟通修改，不必卡合并
- [ ] 里程碑验收通过后，将 dev 合并进 main（唯一合并入口，组员不直推 main）
- [ ] W7 主导模块拼接与冲突裁决；性能优化；安卓 APK + Windows 打包
- [ ] 接口变更仲裁与 `接口约定.md` 维护

### E. 课程文档与答辩（全程，节奏见总计划第八章）

- [ ] 《软件开发计划》主笔（W1 定稿）

## 六、验收标准

- 空库、无推荐、倒计时后台恢复、库关闭模式四个边界场景全部正常；
- 规则引擎对测试用例集（含生肉 + 即食菜冲突、双灶互斥、腌制前置）输出符合安全规则；
- 开饭时间倒推：输入 18:00 开饭，各步骤开始时刻与"开始动手"提示正确；
- 步骤拖拽：交换顺序后时刻即时重算；违反安全规则时震动 + 红条提示原因并回弹；
- 时序执行视图滚动流畅（60fps 目标），悬浮条跨页面状态正确；
- 五份课程文档与实际代码一致，答辩材料可完整演示核心链路。
