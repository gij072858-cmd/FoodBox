# 食匣 FoodBox —— 数据层使用说明

> **面向**：成员二 / 三 / 四（写页面的人） ｜ **交付**：组长 W2 ｜ **一页纸 + 示例代码**
> 配套：《接口约定.md》（数据与接口口径）、《02-开发总计划.md》第七章（接口机制）

---

## 一句话纪律

**页面不碰数据库，只调 Repository 接口。**

`lib/data/local/database.dart` 是共享区里的"内部零件"——页面 import 它就是违规。想看什么数据，就调对应的 Repository；没有你要的方法，走《接口约定.md》第 6 章的变更流程，别自己加。

---

## 1. 四个 Repository 在哪、谁用

全部通过 Riverpod 取用，Provider 定义在 `lib/core/providers.dart`：

| Provider | 接口 | 主要使用人 |
|---|---|---|
| `pantryRepositoryProvider` | `PantryRepository` | 成员二（库页面）、组长（推荐算法） |
| `recipeRepositoryProvider` | `RecipeRepository` | 成员三（菜式页 / 详情页） |
| `scheduleRepositoryProvider` | `ScheduleRepository` | 组长（时序页）、成员三（长按加入时序） |
| `profileRepositoryProvider` | `ProfileRepository` | 成员四（我的页面） |

对应的领域模型（`Item` / `Recipe` / `Step` / `ScheduleItem` / `CookRecord` / `Profile`）在 `lib/data/models/` 下，**不依赖 Drift**，可以放心在页面和组件里使用。

## 2. 读数据：把流接进 Provider，页面用 `ref.watch`

Repository 的 `watchXxx()` 返回 `Stream`，推荐在页面文件里包一层 `StreamProvider`：

```dart
import 'package:flutter_riverpod/flutter_riverpod.dart';
import '../../core/providers.dart';
import '../../data/models/item.dart';

/// 页面级派生 Provider：把 Repository 的流接进 Riverpod
final StreamProvider<List<Item>> pantryItemsProvider =
    StreamProvider<List<Item>>(
  (Ref ref) => ref.watch(pantryRepositoryProvider).watchAll(),
);

class PantryTabPage extends ConsumerWidget {
  const PantryTabPage({super.key});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final AsyncValue<List<Item>> asyncItems = ref.watch(pantryItemsProvider);

    return asyncItems.when(
      data: (List<Item> items) => ListView.builder(
        itemCount: items.length,
        itemBuilder: (_, int i) => FbCard(item: items[i]),
      ),
      loading: () => const Center(child: CircularProgressIndicator()),
      error: (Object e, StackTrace st) => FbEmptyState(title: '加载失败'),
    );
  }
}
```

要一次性读取（不需要实时刷新）就用 `Future` 方法，例如 `getById(id)`、`getAll()`。

## 3. 写数据：`ref.read`，不需要手动刷新

```dart
onPressed: () async {
  await ref.read(pantryRepositoryProvider).create(
        Item(name: '番茄', kind: ItemKind.ingredient),
      );
  // 不用手动刷新 —— 上面 watch 的流会自动推出新数据
},
```

**读写用词的区别**：`ref.watch` 用于 build 里订阅状态；`ref.read` 用于回调 / 事件里触发动作。在 `build` 里用 `read` 会导致界面不更新。

## 5. 几个容易踩的点

- **`isDepleted`（v1.1 新增）**：扣库存到 0 的条目**不会消失**，而是 `isDepleted == true`。库页面请把它**置灰展示**，并给出「移出库 / 加入购物清单」的入口 —— **不要用过滤把它藏掉**（接口约定 3.3）。
- **`ScheduleRepository.add(recipeId)` 是幂等的**：重复长按不会出现两条，只会更新份数，也不会把已排程的条目标回待排。所以长按浮层的「✓」可以放心直调，不用先查一遍。
- **`consume(recipeId)` 由时序模块调用**，菜式模块不要调它——这是"时序 → 库"的闭环动作（接口约定 3.3）。
- **`servings` 默认 2**：与 `Recipe.baseServings` 默认值一致。
- **`watchXxx()` 是实时的**：数据一变就推送，页面不要自己写轮询或手动刷新。
- **`ProfileRepository.watch()` 恒返回 1 行**（单机单用户），不用担心空列表。

## 6. 改完 JSON 记得跑校验脚本

预置数据在 `app/assets/data/`。改完任何 JSON，**推送前先跑一遍**：

```bash
cd app
dart run tool/validate_assets.dart
```

- 全部通过 → 打印 `校验通过：food_items.json / recipes.json / alias_map.json`；
- 有问题 → 逐条列出「文件 + 下标 + 字段」，退出码 1。

**这是 W2 的验收项**：成员二的食材 JSON、成员三的菜式 JSON 提交前都必须先跑通这个脚本。脚本特别检查菜式步骤的**耗时 / 资源占用 / 安全标记**三项——缺一项，组长的时序规则引擎就没法正确排程。

## 7. 别名表（现在不用管）

`assets/data/alias_map.json` 的**结构骨架**已在 W2 就位（含 2 组示例）。真实别名数据与 `AliasTable` 实现由组长在 **W4** 交付，届时 `RecipeMatcher` 会用它把「西红柿」归一到「番茄」。

> 顺带说明：W2 的 `consume` 扣减目前只做**字符级**归一（去空白 + 忽略大小写），别名映射要等 W4 注入 `AliasTable` 后才生效。
