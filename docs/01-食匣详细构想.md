## 第一章 项目定位与设计基调

### 1.1 产品定位

食匣 FoodBox 是一款面向**在家做饭的人**的厨房管理工具，核心解决三个真实痛点：

1. **不知道冰箱里还有什么** → 「库」管理现有食材与调料；
2. **不知道这些能做什么菜** → 「菜式」根据库存推荐可做的菜、按分类学习新菜；
3. **做多个菜时手忙脚乱、顾此失彼** → 「时序」把多道菜的步骤重排成一条时间线，像歌词滚动一样引导操作。

「动态」与「我的」是社区与个人资产层，让用户的做菜成果可以沉淀、分享、复用。

### 1.2 参照风格的裁剪映射

原构想参照网易云音乐的界面语言。音乐 App 与厨房 App 业务不同，需裁剪映射，下表为定稿：

| 网易云设计元素                                | 保留/改造/舍弃 | 食匣中的对应物                     |
| -------------------------------------- | -------- | --------------------------- |
| 卡片化容器、流式重排                             | 保留       | 食材卡片、菜式卡片、动态卡片              |
| 嵌套圆角法则（外 12–16px / 内 6–8px / 胶囊 999px） | 保留       | 全局圆角系统（见 1.3）               |
| 封面底图 + 底部渐变黑色遮罩 + 白色粗体文字               | 保留       | 食材/菜式卡片的图片与蒙版文字             |
| 首屏横向滑动卡片 Carousel                      | 保留       | 库的水平轮转卡片、菜式推荐区              |
| 分块流式列表 Section List（模块标题 + 若干条目）       | 保留       | 菜式下半区分类歌单、我的页面清单            |
| 歌单（左小图 + 右双行文本，每行一条）                   | 保留       | 菜式分类列表、我的三栏清单               |
| 双列非对称瀑布流                               | 保留（期2）   | 动态页笔记流                      |
| 顶部二级频道 Tab（加粗 + 下划线选态）                 | 保留       | 首页顶部「库 / 菜式 / 时序」           |
| 侧边抽屉 Drawer（身份区 + 功能白卡 + 底部设置）         | 改造       | 设置/数据管理/关于等低频入口（见 2.6）      |
| 底部悬浮播放器（旋转唱片 + 跑马灯）                    | 改造       | 全局悬浮计时条（做菜时显示活跃倒计时，见 2.4.4） |
| 极简三段式底部 TabBar                         | 保留       | 首页 / 动态 / 我的                |
| 在线状态头像栏 Stories                        | 舍弃（期1）   | 动态期2 再评估                     |
| VIP 徽标、运营 Banner、商业化标签                 | 舍弃       | 食匣无商业化模块                    |
| 歌词滚动（逐行高亮推进）                           | 保留（核心改造） | 时序流程的步骤滚动引导                 |

### 1.3 全局设计规范（定稿）

**色彩**

| 角色    | 色值            | 用途                      |
| ----- | ------------- | ----------------------- |
| 主背景   | `#F7F8FA` 冷灰  | 页面底色                    |
| 卡片底   | `#FFFFFF`     | 卡片与分组容器                 |
| 品牌强调色 | `#E8442E` 食匣红 | 关键操作、激活态、提醒角标（类比网易云品牌红） |
| 辅助强调  | `#3B7CFF` 蓝   | 话题标签、链接型文字              |
| 主文字   | `#1A1A1A`     | 标题、正文                   |
| 次要文字  | `#8A8F99`     | 时间、计数、弱化信息              |
| 安全/完成 | `#2FA84F`     | 倒计时完成、库存充足标识            |
| 预警    | `#F5A623`     | 食材临期（≤3 天）              |
| 危险    | `#E8442E`     | 食材已过期（复用品牌红，保证克制）       |

> 点缀色可使用低饱和马卡龙色用于分类标签（如海鲜=浅蓝、禽肉=浅橙、蔬菜=浅绿），但每屏不超过 3 种。

**圆角系统**：外层卡片 14px（区间 12–16px）、卡片内嵌缩略图 8px（区间 6–8px）、按钮与胶囊 999px 全圆角。严格遵循"外大内小"的嵌套法则。

**字体层级**

| 层级  | 字号      | 字重      | 用途                   |
| --- | ------- | ------- | -------------------- |
| H1  | 22px    | Bold    | 页面大标题、步骤大字           |
| H2  | 18–20px | Bold    | 模块标题（Section Header） |
| 正文  | 15–16px | Regular | 条目主文字，行距 1.5 倍       |
| 辅助  | 13px    | Regular | 副标题、简介               |
| 弱化  | 12px    | Regular | 时间、计数、角标             |

**栅格与间距**：页面左右边距 16px；卡片间距 12px；模块间垂直间距 24px；瀑布流列间距 8–10px。

**图标**：全线性图标（Line Icons）， stroke 2px，激活态填充实色。禁用杂乱描边。

**动效基调**：页面转场 250ms ease-out；卡片按压缩放 0.97；倒计时、滚动类动效需"可感知但不喧宾夺主"。

## 第二章 功能详述

### 2.0 信息架构总览

```
食匣 FoodBox
├── 首页（顶部 Tab：库 / 菜式 / 时序）
│   ├── 库：现有食材（上）+ 现有调料（下）
│   ├── 菜式：可做推荐（上）+ 分类学习歌单（下）
│   └── 时序：今日做菜流程时间线
├── 动态（期1 UI 占位 + 演示数据，期2 真实化）
└── 我的（身份 + 数据统计 + 三栏菜式清单）
    └── 抽屉：设置 / 数据备份 / 关于
```

「库」为可选模块（见 2.2.5），关闭后首页顶部 Tab 只显示「菜式 / 时序」。

### 2.1 首页框架

- **底部 TabBar**：极简三段式「首页 / 动态 / 我的」，无描边，图标线性、激活态实心加粗，文字无衬线加粗。
- **首页顶部二级 Tab**：「库 / 菜式 / 时序」支持横向滚动与左右滑动手势切换；激活项加粗 + 底部 3px 圆角下划线（品牌红），未激活项浅灰。
- **右上角**：搜索图标（全局搜索食材、调料、菜式）；库开启时旁边有「+」快捷录入入口。

### 2.2 库（可选模块）

#### 2.2.1 页面结构

页面垂直分为上下两个独立区域：

- **上半区：现有食材**
  - 区域标题行：「现有食材」H2 粗体 + 右侧「共 N 项」弱化计数 + 排列切换图标（⇄）。
  - 默认**大卡片水平轮转**：单卡宽高比约 3:4，宽度约占屏宽 42%（一屏露出 2.5 张，暗示可滑）；支持手动滑动 + 闲置 3 秒后缓慢自动滚动（每张停留 2.5 秒，用户触碰即暂停自动滚动 10 秒）。
- **下半区：现有调料**
  - 结构与食材区完全一致（标题行 + 水平轮转）。
  - 调料与食材分区的理由：调料有效期长、消耗慢、通常不作为"吃什么"的决定因素，展示权重应低于食材。

两区各自独立滚动，页面整体也可垂直滚动；当某区卡片多于约 8 张时，自动滚动依然生效但速度放缓，避免眩晕。

#### 2.2.2 卡片视觉规范

每张食材/调料卡片（大卡片模式）：

- 满铺高清图片（比例 3:4，中心裁剪），圆角 14px；
- 底部 40% 高度叠加**向下渐变黑色蒙版**（透明度 0 → 0.65）；
- 蒙版上白色文字，大小有致地标注基本属性：
  - 名称（18px Bold，一行截断）
  - 关键属性行（13px，半透明白 85%）：食材显示「剩余天数 + 数量」（如「剩 5 天 · 约 500g」或粗粒度「剩 5 天 · 快没了」）；调料显示「开封状态 + 数量」
- 右上角小角标（可选）：临期食材显示橙色「3 天」倒计时胶囊；过期显示红色「已过期」。

**基本属性的完整字段集**（卡片只显示 1–2 个，其余在详情页）：名称、分类、数量/份量、单位、购买/入库日期、保质期、到期日、存放位置（冷藏/冷冻/常温）、品牌（调料）、开封状态（调料）、备注、条形码、图片。

#### 2.2.3 排列模式切换

用户可在每个分区独立切换两种排列：

1. **大矩形水平罗列**（默认）：视觉冲击强，适合库存少、快速浏览；
2. **竖直列表模式**：每行一条、高度约 64px，左 48×48 圆角缩略图 + 中间双行文本（名称 + 属性标签，如「冷藏 · 剩 5 天」）+ 右侧状态小图标；限定可视行数（约 5 行）内滚动，信息密度更高，适合库存多的用户。

切换按钮位于分区标题行右侧，带动效过渡（300ms）。

#### 2.2.4 卡片详情页

点击卡片进入详情页，垂直结构自上而下：

1. **顶部大图**（占屏高约 35%，可下滑手势返回）；
2. **有效期区**（紧挨大图下方的第一信息层级）：
   - 若未设置：显示一个小号「+」圆形按钮，点击后**按预置保质期自动算出到期日**（入库日期 + 默认保质期天数，按存放位置校正），用户在弹出层中可修改后确认；
   - 若已设置：显示「到期日 + 剩余天数进度环/进度条」，点击可重新编辑；
   - 同时显示入库日期与存放位置（冷藏/冷冻/常温，影响保质期建议）；
3. **统一格式简介卡**：所有食材/调料的简介遵循同一模板（见下）；
4. **操作区**：编辑信息、调整数量（消耗/补充）、扫码关联条形码、删除条目。

**简介统一模板**（字段固定、顺序固定，保证全库调性一致）：

```
【是什么】一两句话说明该食材/调料是什么、风味特点。
【怎么用】常见用法、适合搭配的菜式类型。
【怎么存】推荐存放方式与大致保质期参考。
【小贴士】一条冷知识或挑选技巧（可选）。
```

简介数据预置于本地食材基础库，用户可编辑；用户自建条目按模板填空。

#### 2.2.5 录入方式与扫码

- **手动录入**：搜索本地预置食材库（约 200–300 个常见条目，含名称、分类、默认保质期、默认存放位置、简介模板）→ 选中后填数量与日期 → 完成。数量支持**双模式自选**：粗粒度（有 / 不多 / 快没了）或精确数量 + 单位（500g、3 个），条目创建后可随时切换。找不到可「自建条目」。
- **扫码录入**：调用摄像头扫描商品条形码 → 在本地条码映射表中匹配 → 命中则自动填入名称/品牌/默认保质期 → 未命中则引导用户手动选择食材并**关联该条码**（下次扫同一商品直接命中，映射关系随使用自学习增长）。
- 拍照识别食材（AI 图像识别）列入远期愿景，不在期1 与期2 的承诺范围（见第四章）。

#### 2.2.6 库存消耗联动

- 时序流程执行完成后（见 2.4），按菜式配方自动扣减对应食材数量，库存归零的条目自动灰显并提示「已用完，是否移出库/加入购物清单」；
- 用户也可在详情页手动调整数量（如实际用量与配方不符时）。

#### 2.2.7 库的降级方案（库功能关闭时）

在设置中可关闭「库」模块：

- 首页顶部 Tab 隐藏「库」，仅剩「菜式 / 时序」；
- 菜式推荐退化为「全部菜式按热度/最新排序」，不再计算"现在能做"；
- 菜式详情页中「缺失食材」区块替换为「所需食材清单（自核对）」静态列表；
- 时序、长按加入时序、我的三栏清单等功能完全不受影响；
- 库存数据保留不删除，重新开启后恢复联动。

### 2.3 菜式

#### 2.3.1 页面结构

垂直上下两部分：

**上半区：推荐区**（横向轮转卡片，视觉规范与库卡片一致：3:4 竖卡 + 底部渐变蒙版 + 白色粗体菜名）

- 「现在就能做」：所需食材与调料在库中全部齐活的菜式；
- 「差一点就能做」：仅缺 ≤2 种食材的菜式（阈值定稿为 2），蒙版上额外标注缺失项，如「缺：蒜、料酒」；
- 两类在同一横滑区内混排，用角标区分（绿点=可做，橙点=差一点）；若库功能关闭，本区退化为「为你推荐」（按收藏热度与新鲜度排序）。

**下半区：分类学习歌单**

- 双维度分类 Tab 或分组：
  - 按主食材：海鲜 / 鸡肉 / 鸭肉 / 猪肉 / 牛肉 / 蔬菜 / 蛋豆制品 / 主食面点 …
  - 按菜系风格：粤菜 / 川菜 / 湘菜 / 鲁菜 / 江浙菜 / 家常菜 / 快手菜 / 汤羹 …
- 每个分类是一张「歌单卡」（横排三卡或两列网格，封面图 + 分类名 + 菜式数量）；
- 点进分类 → 列表页：每行一条，左侧 64×64 圆角小图 + 右侧菜名（16px）与极简介绍（13px 灰，一行截断，如「鲜辣下饭 · 25 分钟 · 中等难度」）；
- 列表支持按耗时/难度/收藏数排序。

#### 2.3.2 菜式详情页（核心页面，设计重心）

进入详情页后的垂直信息流：

1. **成品大图**：满宽，比例约 16:10，顶部沉浸式（状态栏透明）；
2. **标题区**：菜名（22px Bold）+ 属性胶囊行（耗时 / 难度 / 菜系 / 份量基准）；
3. **缺失食材区**（库开启时显示）：列出还缺什么、缺多少，附「一键加入购物清单」（F1，期1 必做）；
4. **食材与调料清单**：两列整齐排版，每项含用量；支持「几人份」缩放（1–6 人份），用量自动换算（F2，期1 必做）；
5. **分享者信息**：下滑可见「xxx 分享于 M月D日」（期1 为官方内容，显示"食匣官方"；期2 动态上线后显示真实用户）；
6. **步骤流程区**（核心交互）：
   - 每个步骤 = **上方大字文字**（18–20px Bold，一句话操作指令）+ **下方小字分割线时间**（12px 灰 + 细分隔线，标注该步骤耗时，如「──── 8 分钟 ────」）；
   - 步骤之间保留充足空行（约 32px），保证节奏感与可读性；
   - **点击步骤文字** → 弹出该步骤的照片流（多图横滑）或短视频（如有素材），沉浸式查看后返回；无图步骤允许留空，点击后仅展开文字详解，UI 优雅降级（不显示空图占位框）。步骤中的烹饪术语（如"焯水""勾芡"）可点开查看名词解释（F8 期1 范围，词条数据见术语表）；
   - **点击分割线时间** → 唤出**水平倒计时条**（见 2.3.3）；
7. **底部操作栏（吸底）**：收藏（喜欢）/ 标记为「想做」/ 加入时序 /「我做过」打卡。

#### 2.3.3 水平倒计时条（重点打磨的组件）

- 形态：从分割线处展开的一条水平进度条，宽度撑满内容区，高约 8px，圆角胶囊；
- 行为：点击后**从左向右流逝**（填充色自左向右推进，或底色自右向左消减——两种方向待打样确认，推荐"填充从左向右生长至满格即完成"，更符合直觉），平滑 60fps 滚动；
- 进行中：条上居中显示剩余时间（mm:ss），右侧小铃铛图标可切换到时提醒方式（震动/铃声/静音）；
- 完成：整条变为安全绿，轻微弹跳动效 + 提示音 + Toast「『翻炒入味』时间到」；
- 多个倒计时可并行存在（时序模式下的刚需），活跃倒计时汇总显示在全局悬浮计时条（见 2.4.4）；
- 倒计时在后台继续运行，回前台时状态正确恢复。

#### 2.3.4 长按加入时序

- 在菜式卡片、菜式列表条目、详情页上**长按** → 弹出悬浮式操作浮层，主按钮为大号「+」；
- 点击「+」→ 变为「✓」并伴随轻动效，该菜式进入时序待做清单；
- 再次点击「✓」→ 取消加入；
- 浮层同时提供次级操作：收藏 / 标记想做 / 查看详情；
- 已加入时序的菜式在卡片右上角显示小勾角标；
- 选好后点击顶部「时序」Tab 跳转查看排程结果。

### 2.4 时序

#### 2.4.1 功能定义

用户把想做的多道菜加入时序后，时序模块根据规则**自动重排所有菜的所有步骤**，生成一条完整的做菜时间线，引导用户按顺序执行，达到：最省事（减少切换与等待）、最省时（能并行的并行，总时长最短）、最安全（生熟分开、油温火候等危险步骤有提示）。

#### 2.4.2 排程规则引擎（期1 实现：确定性规则，非 AI）

输入：时序清单中每道菜的步骤列表（每步含：耗时、占用资源[灶台/案板/手部操作/等待]、前置约束、安全标记）。
输出：一条合并后的时间线（步骤序列 + 每步开始/结束时间 + 并行标注）。

规则按优先级排序：

1. **安全规则（最高优先，不可违反）**
   - 生熟案板分离：处理生肉的案板步骤之后、处理即食食材之前，强制插入「清洗案板与刀具」步骤（2 分钟）；
   - 腌制、泡发类步骤必须排在其后续烹饪步骤之前，且间隔 ≥ 腌制时长；
   - 同一灶台同一时间只允许一个"需看火"步骤；
2. **省时规则**
   - 等待类步骤（炖煮、腌制、醒发）启动后，其等待窗口内插入其他菜的手部操作步骤（并行）；
   - 耗时最长的菜的关键路径优先启动（最长工序先行）；
3. **衔接规则**
   - 每道菜的最后一个烹饪步骤尽量贴近预计开饭时间（热菜趁热上桌）；
   - 绿叶菜等"出锅即食"的菜排在时间线末端；
4. **缓冲规则**：时间线末尾预留 10% 缓冲；相邻不同菜的步骤间插入 1 分钟「收拾衔接」微步骤（可关闭）。

算法实现：贪心 + 约束检查的规则引擎（先按规则 2 生成初排，再用规则 1/3 校正），期1 不追求全局最优，追求"合理、可解释、可手动调整"。

#### 2.4.3 时序展示（歌词滚动式）

- 整体形态与菜式详情的步骤流一致：**大字步骤 + 分割线时间**，逐行推进；
- 时间轴从「现在开始」或用户设定的「开饭时间」倒推生成，每行步骤左侧标注预计时刻（如 17:42）；
- 执行模式：当前步骤高亮放大，已完成步骤置灰打勾并轻微收起，未来步骤正常灰度显示——整体滚动体验类比歌词滚动；
- 属于同一道菜的步骤用左侧彩色细条标识（每道菜一个低饱和色），跨菜穿插时一目了然；
- 分割线时间同样可点击唤出倒计时条；
- 支持手动微调：长按拖拽交换步骤顺序（系统提示该调整是否违反安全规则）；
- 顶栏显示：预计总时长、预计完成时刻、「开始执行」按钮。

#### 2.4.4 全局悬浮计时条（由网易云悬浮播放器改造而来）

- 当时序执行中或存在活跃倒计时时，底部 TabBar 上方 8–12px 处浮出胶囊条；
- 内容：左侧为当前步骤缩略文字（跑马灯滚动，如「红烧鱼 · 焖煮中」），中间为最近一个倒计时的剩余时间，右侧为「暂停/查看」操作；
- 点击胶囊 → 返回时序执行页；
- 无论用户在 App 哪个页面，计时状态始终可见——这是"最省事最安全"承诺的载体。

#### 2.4.5 两期范围声明

时序是本项目技术含量最高、原创性最强的功能。两期目标：

- **期1 必做**：UI 完整设计与实现、待做清单管理、规则引擎 v1（2.4.2 的确定性规则）、歌词滚动执行视图、**开饭时间倒推**、**步骤拖拽调整（含安全规则校验提示）**、倒计时联动、悬浮计时条；
- **期2**：语音播报步骤（F11）、排程规则扩充；
- **远期愿景（不承诺期次）**：AI 智能排程、多厨房多灶具建模。

#### 2.5.2 期2 完整构想（写入需求分析的远期规划章节）

## 第四章 不切实际之处与改进建议

> 以下按"原构想 → 问题 → 改进方案"逐条列出，均已按改进方案写入第二章。

**1. 扫条形码直接识别食材**

- 问题：国内没有免费、完整、合法的"商品条码 → 食材"映射数据库。超市包装食品条码覆盖率尚可，但散装蔬菜、肉类、水产根本没有条码；第三方 API 要么收费要么覆盖差。若承诺"扫码即识别"，实际体验会大量落空。
- 改进：**预置条码 + 自学习记忆**（2.2.5）。预置常见包装品（调料、牛奶、包装食材）条码；未命中时用户手动选一次食材并记住该条码，下次直接命中。把"识别率"问题转化为"越用越聪明"的卖点，答辩时反而是亮点。

**2. 所有食材/调料都要有"高清图片"**

- 问题：数百种食材的统一定调高清图，无版权免费图源几乎不存在；实拍工作量巨大（打光、构图、后期，团队无此人力）；网络图源有版权风险，上传 GitHub 公开仓库后风险放大。
- 改进（按组长意见修订）：**真实高清图优先**——① 预置条目尽可能先导入真实高清图片，随数据录入逐批配图（小范围内使用，不涉及版权问题）；② 暂无高清图的条目用 AI 生成的统一风格图兜底（构图、光线、背景统一）；③ 用户条目允许自拍上传；④ 图片资源目录设计为可整体替换，版式与图解耦（"图可换、版式不动"作为设计约束）。高清图收集随食材/菜式数据录入同步进行（成员二负责食材图、成员三负责菜式图）。

**3. 「根据库存推荐可做的菜式」**

- 问题：真正准确的推荐需要每道菜配方结构化、食材别名归一（"西红柿=番茄"）、份量匹配，属于数据工程 + 算法的双重工作量，2 个月做不精。
- 改进：MVP 用**库存匹配度**简化算法——菜式的必需食材清单与库中条目做集合匹配（含一张人工维护的别名表），输出「可做 / 缺 N 样」。别名表随初始菜式数据一起人工维护，规模可控。

**4. 时序算法"最省事最节省时间也最安全"**

- 问题：这是带约束的组合优化问题，"最安全"还涉及食品安全领域知识（生熟交叉、中心温度、油温），不可能 2 个月做出可信的智能最优解。
- 改进：期1 承诺**规则引擎 v1**（2.4.2）：确定性规则、结果可解释、安全规则硬编码为不可违反约束。对外表述为"按食品安全与省时规则自动排程"，不使用"AI""智能最优"等词。答辩时把规则表讲清楚就是加分项。

**5. 动态社区（含分享、调入他人菜式）**

- 问题：需要账号体系、服务端、内容审核，2 个月 + 无后端经验 = 必烂尾；即使做出来，无真实用户也是空壳。
- 改进：期1 UI 占位 + 期2 真实化（2.5），技术架构预留 Repository 云接口层，期2 接 Supabase 即可补上。课程文档中将动态写入"远期规划"章节，展示规划能力而非半成品。

**6. 自动滚动 + 手动滚动并存的卡片区**

- 问题：自动滚动若处理不好会与用户手势打架、引起眩晕，属于"听起来简单、调起来磨人"的细节。
- 改进：明确交互规则（闲置 3 秒才启动、触碰即暂停 10 秒、速度随卡片数放缓），并把该组件交给成员四在 W2 以公共组件形式先行打样，全组复用，避免每人各写一版。

**7. 多倒计时并行 + 全局悬浮条 + 后台运行**

- 问题：Flutter 中多个精准倒计时并行、页面切换与后台挂起后的状态恢复，是新手最容易翻车的点（Timer 漂移、后台被杀）。
- 改进：倒计时不依赖 Timer 周期计数，而记录"结束时间戳"，UI 每帧按当前时间差渲染——挂起恢复天然正确；提醒用本地通知（flutter_local_notifications）兜底。此方案作为技术规范写入成员三与组长的任务书。

## 附录 数据模型草案

> 详细字段以概要设计文档为准，此处为分工对齐用的最小约定。

- **食材/调料条目 Item**：id、名称、分类、类型（食材/调料）、数量、单位、入库日期、保质期天数、到期日、存放位置、开封状态（调料）、条码、图片路径、简介四段、是否自建
- **菜式 Recipe**：id、菜名、封面图、菜系、主食材分类、耗时、难度、份量基准、适宜月份标签（F12）、食材清单[条目+用量+是否必需]、调料清单、步骤列表、简介、来源（官方/用户）、分享者、分享日期
- **步骤 Step**：序号、大字指令文字、标准耗时（分钟）、占用资源（灶台/案板/手/等待）、安全标记、照片流[图片路径]、视频路径（可空）
- **时序任务 ScheduleItem**：菜式 id、加入时间、份数、状态（待排/已排/完成）
- **做菜记录 Record**：菜式 id、完成时间、复盘笔记（F14）
- **用户档案 Profile**：昵称、头像路径、经验值 XP、厨阶等级、累计顿数、三栏清单（喜欢/做过/想做的菜式 id 集合）
