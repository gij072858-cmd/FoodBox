## 1. 引言

### 1.1 编写目的

把"用户想要什么"整理成可验证的需求条目，作为设计、开发、测试与验收的共同基准。
本文档是"功能是否做到"的最终判定依据——测试用例从这里出，答辩问"这个需求怎么来的"也从这里答。

### 1.2 需求来源

| 来源 | 说明 |
|---|---|
| 用户痛点访谈（组内 + 亲友） | 三大痛点：不知道冰箱有什么、不知道能做什么、多菜并行手忙脚乱 |
| 竞品分析 | 现有产品各自只管一段（记账类管库存、菜谱类管做法），无产品把链路串通 |
| 团队自评与裁剪 | 见《01-食匣详细构想》第四章「不切实际之处与改进建议」7 条 |
| 需求确认会 | W1 内一次，逐条过歧义清单结论，全员确认 |

### 1.3 需求编号规则

`FR-<模块>-<序号>`：功能需求；`NFR-<类别>-<序号>`：非功能需求。
模块代号：`PAN` 库 / `REC` 菜式 / `SCH` 时序 / `PRF` 我的 / `FED` 动态 / `PKG` 期1 功能包 / `SYS` 系统级。

## 2. 用户与场景分析

### 2.1 目标用户

**主要用户**：在家做饭的人（学生、上班族、家庭主厨），典型特征：

- 每周做饭 3 次以上，冰箱有食材但缺乏系统管理；
- 会做几道拿手菜，想换花样但缺灵感；
- 一次做多道菜时容易手忙脚乱。

**次要用户**：想学做菜的新手（需要步骤引导与术语解释）。

### 2.2 典型场景

| 场景 | 用户诉求 | 对应需求 |
|---|---|---|
| S1 周末采购回来入库 | 快速录入，知道每样能放多久 | FR-PAN-01 / 02 / 05 |
| S2 傍晚 6 点站在冰箱前 | 用现有食材能做什么，缺什么 | FR-REC-01 / 02 / FR-PKG-01 |
| S3 决定做三道菜 | 怎么安排顺序最省事、几点开始动手 | FR-SCH-01 / 02 / 03 |
| S4 边做边看 | 当前步骤是什么、还有几分钟 | FR-SCH-04 / 05 / FR-PKG-02 |
| S5 做完复盘 | 记录做过什么、积累成就感 | FR-PRF-02 / 03 / FR-PKG-03 |
| S6 换手机 / 换电脑 | 数据能带走 | FR-PKG-04 |

### 2.3 使用约束

- **单机单用户**（Q12-A）：期1 无账号体系，数据存本地；
- **双端**：安卓为主（移动端能力完整），Windows 为管理端（扫码降级为手动输入，Q11-B）；
- **离线可用**：核心功能不依赖网络。

## 3. 功能需求

### 3.0 需求全景（信息架构）

```
食匣 FoodBox
├── 首页（顶部二级 Tab：库 / 菜式 / 时序）
│   ├── 库：现有食材（上）+ 现有调料（下）        ← 可选模块，可关闭
│   ├── 菜式：可做推荐（上）+ 分类学习歌单（下）
│   └── 时序：今日做菜流程时间线
├── 动态（期1 UI 占位 + 演示数据；期2 真实化）
└── 我的（身份 + XP 体系 + 三栏菜式清单）
    └── 抽屉：设置 / 数据备份 / 关于
```

### 3.1 库模块（FR-PAN）

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-PAN-01 | 库页面分上下两个独立区域：「现有食材」与「现有调料」，各自独立滚动，整页可垂直滚动 | 高 | 两区互不影响；调料区权重低于食材区 |
| FR-PAN-02 | 卡片默认「大卡片水平轮转」：3:4 竖卡，宽度约屏宽 42%，一屏露出约 2.5 张；支持手动滑动；**闲置 3 秒后缓慢自动滚动（每张停留 2.5 秒），触碰即暂停 10 秒** | 高 | 自动滚动与手势不打架；卡片 > 8 张时速度放缓 |
| FR-PAN-03 | 每区可独立切换排列模式：水平大卡 ⇄ 竖直紧凑列表（每行约 64px，左 48×48 缩略图 + 中间双行文本），切换带 300ms 过渡 | 中 | 两种模式均可完整浏览，切换不丢位置 |
| FR-PAN-04 | 卡片视觉：满铺 3:4 中心裁剪图（圆角 14px）+ 底部 40% 向下渐变黑色蒙版（透明度 0→0.65）+ 白色文字（名称 18px Bold 一行截断；属性行 13px 半透明白 85%） | 高 | 属性行显示「剩 N 天 · 数量」；临期右上角橙色胶囊、过期红色「已过期」（Q1-B / Q2-B） |
| FR-PAN-05 | 详情页自上而下：顶部大图（约 35% 屏高，可下滑返回）→ 有效期区 → 简介卡 → 操作区 | 高 | 有效期区是第一信息层级；点击「+」按预置保质期自动算出到期日，弹出层可修改（Q3-C） |
| FR-PAN-06 | 简介统一模板：【是什么】/【怎么用】/【怎么存】/【小贴士】（可选），字段与顺序固定 | 中 | 预置于基础库，用户可编辑；自建条目按模板填空 |
| FR-PAN-07 | 手动录入：搜索本地预置食材库（200–300 条）→ 选中 → 填数量与日期 → 完成；找不到可自建条目 | 高 | 数量支持双模式：粗粒度（有 / 不多 / 快没了）或精确数量 + 单位（Q5-C） |
| FR-PAN-08 | 扫码录入：扫商品条码 → 匹配本地条码映射表 → 命中自动填名称/品牌/默认保质期；未命中引导手动选择并**关联该条码**，下次直接命中（自学习） | 中 | 电脑端降级为手动输入条码 |
| FR-PAN-09 | 库存消耗联动：时序执行完成后按配方自动扣减；数量归零条目**灰显并提示**「已用完，是否移出库 / 加入购物清单」 | 高 | 同一菜式多条食材在同一事务内扣减 |
| FR-PAN-10 | 库模块可关闭：首页顶部 Tab 只显示「菜式 / 时序」；菜式推荐退化为按热度/最新排序；菜式详情页「缺失食材」区替换为「所需食材清单（自核对）」；**库存数据保留不删除**，重新开启后恢复联动 | 中 | 时序、长按加入时序、三栏清单不受影响 |

### 3.2 菜式模块（FR-REC）

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-REC-01 | 推荐区（横滑卡片）：区分「现在就能做」（库存齐活）与「差一点就能做」（仅缺 ≤2 种必需食材），两类混排、角标区分（绿点 / 橙点）（Q6-A） | 高 | 差一点类在蒙版上标注缺失项，如「缺：蒜、料酒」 |
| FR-REC-02 | 库关闭时推荐区退化为「为你推荐」（按收藏热度与新鲜度排序） | 中 | 不计算"现在能做" |
| FR-REC-03 | 分类学习歌单：双维度分类（按主食材：海鲜/鸡肉/鸭肉/猪肉/牛肉/蔬菜/蛋豆制品/主食面点…；按菜系风格：粤菜/川菜/湘菜/鲁菜/江浙菜/家常菜/快手菜/汤羹…） | 高 | 每分类为一张「歌单卡」（封面图 + 分类名 + 菜式数量） |
| FR-REC-04 | 分类列表页：每行一条，左 64×64 圆角小图 + 右侧菜名（16px）与极简介绍（13px 灰，一行截断，如「鲜辣下饭 · 25 分钟 · 中等难度」）；支持按耗时/难度/收藏数排序 | 中 | 排序切换生效 |
| FR-REC-05 | 详情页信息流：成品大图（16:10 沉浸式）→ 标题区（菜名 22px Bold + 属性胶囊：耗时/难度/菜系/份量基准）→ 缺失食材区（库开启时）→ 食材与调料清单（两列，支持 1–6 人份换算）→ 分享者信息 → 步骤流程区 → 底部吸底操作栏 | 高 | 收藏 / 想做 / 加入时序 / 我做过打卡 四个操作 |
| FR-REC-06 | 步骤流：每步 = 上方大字文字（18–20px Bold）+ 下方小字分割线时间（12px 灰，如「──── 8 分钟 ────」）；步骤间空行约 32px | 高 | 节奏感与可读性达设计规范 |
| FR-REC-07 | 点击步骤文字 → 弹出该步骤照片流（多图横滑）或短视频；**无图步骤允许留空，点击仅展开文字详解，不显示空图占位框**（Q14-C 优雅降级） | 中 | 术语（焯水/勾芡）可点开看解释（F8） |
| FR-REC-08 | 点击分割线时间 → 唤出水平倒计时条 | 高 | 见 FR-PKG-02 |
| FR-REC-09 | 长按卡片 / 列表条目 / 详情页 → 弹出浮层，主按钮大号「+」；点击变「✓」加入时序，再次点击取消；浮层另提供收藏/想做/查看详情；已加入的菜式卡片右上角显示小勾角标 | 高 | 只调 `ScheduleRepository.add`，不关心时序实现 |
| FR-REC-10 | 期1 官方菜式 30–50 道，每道含完整步骤与耗时 | 高 | 步骤的「耗时 + 资源占用 + 安全标记」三项标注完整 |

### 3.3 时序模块（FR-SCH）—— 项目技术核心

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-SCH-01 | 规则引擎自动重排所有菜的所有步骤，生成一条完整时间线 | 高 | 输出含步骤序列 + 每步起止时刻 + 并行标注 |
| FR-SCH-02 | 规则按优先级执行：**安全规则**（生熟案板分离：处理生肉步骤之后、处理即食食材之前强制插入「清洗案板与刀具」2 分钟；腌制/泡发必须排在其后续烹饪之前且间隔 ≥ 腌制时长；同一灶台同一时间只允许一个需看火步骤）→ **省时规则**（等待窗口中插入其他菜的手部操作；最长工序先行）→ **衔接规则**（每道菜最后烹饪步骤贴近开饭时间；出锅即食的绿叶菜排在末端）→ **缓冲规则**（末尾预留 10% 缓冲；相邻不同菜之间插入 1 分钟「收拾衔接」微步骤，可关闭） | 高 | 安全规则**不可违反**；结果为确定性、可解释、可手动调整 |
| FR-SCH-03 | **开饭时间倒推**（Q7-A，期1 必做）：输入开饭时刻，倒推各步骤开始时刻与"几点开始动手"提示 | 高 | 输入 18:00，各步骤开始时刻与提示正确 |
| FR-SCH-04 | 时序展示（歌词滚动式）：大字步骤 + 分割线时间逐行推进；时间轴每行左侧标注预计时刻（如 17:42）；当前步骤高亮放大、已完成置灰打勾并轻微收起、未来步骤灰度显示；同一道菜的步骤用左侧彩色细条标识 | 高 | 滚动体验流畅（60fps 目标） |
| FR-SCH-05 | 顶栏显示预计总时长、预计完成时刻、「开始执行」按钮 | 中 | 数值与排程结果一致 |
| FR-SCH-06 | **步骤拖拽调整**（Q8-A，期1 必做）：长按拖拽交换步骤顺序，拖后重算时刻并校验安全规则，**违规时震动 + 红条提示原因并回弹** | 高 | 违规提示能说清"违反了哪条规则" |
| FR-SCH-07 | 全局悬浮计时条：时序执行中或存在活跃倒计时时，底部 TabBar 上方 8–12px 浮出胶囊条；内容为当前步骤缩略文字（跑马灯）+ 最近一个倒计时剩余时间 + 暂停/查看；点击返回执行页；**跨页面始终可见** | 高 | 任意页面均可看到计时状态 |
| FR-SCH-08 | 执行完成闭环：扣库存 → 写做菜记录 → XP 结算与厨阶更新 | 高 | 三者一致，无部分成功状态 |
| FR-SCH-09 | 待做清单管理：可移除条目、调整份数 | 中 | 清单状态与首页角标一致 |

### 3.4 我的（FR-PRF）

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-PRF-01 | 身份区：圆形裁切头像（直径约 88px，可点击更换）+ 昵称（18px Bold）+ 两项核心数据（等级数、累计做过 N 顿饭） | 中 | 13px 灰，横向紧凑排布 |

| FR-PRF-04 | 「我做过的」条目附「再次加入时序」快捷入口 | 中 | 一键加入 |
| FR-PRF-05 | 抽屉导航（覆盖约 80% 宽度 + 右侧半透明压暗）：顶部身份区；功能白卡分组（库开关、排列模式默认值、提醒设置、数据备份与导出、关于食匣）；底栏（设置 / 意见反馈，纯本地记录） | 中 | 库开关切换后首页 Tab 立即变化 |

## 4. 非功能需求

| 编号 | 类别 | 需求 |
|---|---|---|
| NFR-01 | 性能 | 列表滚动与页面转场无明显掉帧，目标 60fps（演示机实测）；冷启动可接受 |
| NFR-02 | 可靠性 | 倒计时在后台挂起 / 页面切换 / 多倒计时并行下状态正确恢复（靠结束时间戳方案保证） |
| NFR-03 | 易用性 | 核心链路从"打开 App"到"开始做菜"不超过 4 步；空态、加载态、错误态均有设计（精致空态优先于空白页） |
| NFR-04 | 一致性 | 全量页面遵守《01-食匣详细构想》1.3 设计规范：色彩、圆角（外大内小嵌套）、字号层级、间距栅格；**禁止硬编码色值** |
| NFR-05 | 可维护性 | 分层架构（表现层 / 领域层 / 接口层 / 数据层）；跨模块只通过接口通信；公共组件在 `widgets/` 收口 |
| NFR-06 | 可扩展性 | Repository 接口层隔离数据访问，期2 云端实现即插即用；组件全部引用 Theme 常量，深色模式零重构 |
| NFR-07 | 兼容性 | 安卓（主力）+ Windows 桌面（管理端）；电脑端明确降级项已在 Q11-B 确认 |
